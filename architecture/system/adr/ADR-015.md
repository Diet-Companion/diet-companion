context:
  text: REQ-009 needs a range per nutrient (calories, protein, fat). A change on day D applies to D and later days, and earlier
    days keep their range (AC-005, AC-006). The journal will ask for the range in force on a date. A closed day never changes
    (R-013, AC-011), but closing does not exist yet (REQ-011). There is no table for ranges. Migrations are forward-only and
    must work with the previous revision running (ADR-008/C-001, C-002). Only CMP-002 reaches the database (ADR-003/C-002).
    Ranges are whole numbers from 0 upward with minimum not above maximum (R-011).
  cites:
  - REQ-009
  - REQ-009/AC-005
  - REQ-009/AC-006
  - REQ-009/AC-011
  - R-011
  - R-013

options:
- key: a
  summary: New table target_ranges with one row per nutrient and effective date (primary key nutrient, effective_from). A
    save on day D inserts the row for D or overwrites it if D already has one. The range in force on X is the row with the
    greatest effective_from not after X.
  satisfies:
  - REQ-009/AC-005
  - REQ-009/AC-006
  - ADR-008/C-001
  - ADR-008/C-002
  pros: Smallest model. The range on a date is one indexed read on the primary key. Earlier rows are never touched, so past
    days keep their range. New table only, so the previous revision keeps working.
  cons: A second save on the same day replaces the first, so what an earlier same-day save said is not kept. A closed day
    is not protected by this table alone.
  cost: One migration and store and handler code in CMP-002. Build effort not stated (A-008).
  reversibility: costly
  risks: A later feature that recomputes a closed day from this table would see a same-day change. Mitigated by ADR-015/C-004
    and integration tests on real PostgreSQL (ADR-008/C-004).
  constraints:
  - id: ADR-015/C-001
    statement: 'Migration 006 is forward-only and adds only the new table target_ranges: nutrient text not null with a check
      in (calories, protein, fat), effective_from date not null, minimum integer not null check minimum >= 0, maximum integer
      not null check maximum >= minimum, primary key (nutrient, effective_from). It inserts no rows, so the previous revision
      keeps working.'
    kind: data
    check: review
  - id: ADR-015/C-002
    statement: effective_from is set only by CMP-002 from today's date as ADR-016 defines it, never from a request. A save
      runs in one transaction and writes only the row (nutrient, today) by insert or overwrite. Rows with an earlier effective_from
      are never updated, and no row is physically deleted.
    kind: data
    check: review
  - id: ADR-015/C-003
    statement: The range in force for a nutrient on date X is the row with the greatest effective_from not after X, or none.
      One shared function in CMP-002 answers it for getTargetRanges and getTargetRangesOn.
    kind: data
    check: review
  - id: ADR-015/C-004
    statement: A closed day keeps the ranges it was closed with on its own record. Its result is never recomputed from target_ranges
      after closing. The design of REQ-011 must provide this.
    kind: interface
    check: review
  affects:
  - CMP-002
  - IF-001
  consequences: IF-001 1.4.0 reads a range for today or for any date. Only CMP-002 owns the table. The journal reads ranges
    through IF-001 only.
  cites:
  - REQ-009/AC-005
  - REQ-009/AC-006
  - ADR-008/C-002
  - A-008
- key: b
  summary: 'Append-only history: target_ranges has a generated sequence id, nutrient, effective_from, minimum and maximum.
    Every save inserts a row. The range in force on X is the row with the greatest effective_from not after X, ties broken
    by the highest sequence id.'
  satisfies:
  - REQ-009/AC-005
  - REQ-009/AC-006
  - ADR-008/C-001
  - ADR-008/C-002
  pros: Every save is kept, so what was in force at any moment of a day can be reconstructed. No overwrite. Still one indexed
    read with an index on (nutrient, effective_from, id desc).
  cons: More rows and a tie-break rule. No source asks for the intra-day history. A closed day is still not protected by this
    table alone.
  cost: One migration and slightly more store code than a. Build effort not stated (A-008).
  reversibility: costly
  risks: Forgetting the tie-break returns an older same-day range. Mitigated by one shared read function and integration tests.
  constraints:
  - id: ADR-015/C-005
    statement: Migration 006 is forward-only and adds only target_ranges with id bigint generated always as identity primary
      key, nutrient, effective_from, minimum and maximum as in ADR-015/C-001 and a non-unique index on (nutrient, effective_from,
      id desc). Rows are only inserted, never updated or deleted. ADR-015/C-002 holds except that a save always inserts.
    kind: data
    check: review
  - id: ADR-015/C-006
    statement: The range in force on X is the row with the greatest effective_from not after X, and among those the highest
      id. ADR-015/C-004 holds unchanged.
    kind: data
    check: review
  affects:
  - CMP-002
  - IF-001
  consequences: Same interface as option a, with a fuller history in the database.
  cites:
  - REQ-009/AC-006
  - ADR-008/C-002
  - A-008
- key: c
  summary: Keep only the current range per nutrient (one row, overwritten on every save). The journal copies the range onto
    each day when that day is created or closed.
  satisfies:
  - REQ-009/AC-005
  pros: Smallest table. No effective-dating logic in targets.
  cons: A day's range exists only if the journal stored it. An open past day has no stored range unless the journal copied
    it earlier, so AC-006 depends on a design that does not exist. Journal and targets are coupled. The range on date X is
    not one read from targets.
  cost: Smaller migration, larger journal design later. Build effort not stated (A-008).
  reversibility: one-way
  risks: Once a save overwrites the row, the earlier range is gone for every day that was not copied, and it cannot be rebuilt.
  constraints:
  - id: ADR-015/C-007
    statement: target_ranges holds one row per nutrient and is overwritten on save. Every consumer that must keep a day's
      range stores its own copy at the time the day is created or closed.
    kind: data
    check: review
  affects:
  - CMP-002
  - IF-001
  consequences: getTargetRangesOn could answer only for today. The journal design inherits the history duty.
  cites:
  - REQ-009/AC-006
  - A-008
recommended:
  option: a
  reason: It meets AC-005 and AC-006 with the smallest model, answers the range on a date in one primary-key read as the ticket
    asks, and adds only a new table (ADR-008/C-002). Option b adds history no source needs; option c cannot keep an open past
    day's range.
