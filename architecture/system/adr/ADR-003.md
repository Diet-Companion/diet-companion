context:
  text: The catalog holds about 100 products and 50 dishes as an estimate, with no limit (REQ-007 AC-004). R-003 needs uniqueness
    of name plus shop ignoring case and extra spaces; R-002 needs required values. Soft-deleted products exist (R-006). Later
    areas will add day logs and measurements; their volumes are not stated.
  cites:
  - REQ-007
  - knowledge/rules/catalog/R-002.md
  - knowledge/rules/catalog/R-003.md
options:
- key: a
  summary: Embedded SQLite file on a persistent volume attached to the backend container, with scheduled file backups.
  satisfies:
  - REQ-007
  - REQ-003
  pros: No separate database service; trivial at this size.
  cons: Ties the backend to one instance and a volume; backup and restore are ours to run.
  cost: Volume fees are not stated (A-001).
  reversibility: two-way
  risks: Losing the volume without a good backup loses all data.
  constraints:
  - id: ADR-003/C-001
    statement: Only CMP-002 opens the database file; backups are taken and a restore is tested.
    kind: data
    check: review
  affects:
  - CMP-002
  consequences: The backend can run only as a single instance, which fits one user.
  cites:
  - REQ-007
  - A-001
- key: b
  summary: Managed relational database service, reached over the network by the backend.
  satisfies:
  - REQ-007
  - REQ-003
  pros: The platform runs backups and durability; the backend container stays stateless as ADR-001/C-002 asks.
  cons: A separate service to provision, with a recurring fee.
  cost: Not stated by any source; open assumption A-001.
  reversibility: two-way
  risks: Provider lock-in is limited because the data is standard relational.
  constraints:
  - id: ADR-003/C-002
    statement: Only CMP-002 connects to the database; the name-plus-shop uniqueness of R-003 is also enforced by a database
      constraint on normalised values.
    kind: data
    check: review
  affects:
  - CMP-002
  consequences: Connection details are provided to the backend through hosting configuration, not code.
  cites:
  - REQ-007
  - knowledge/rules/catalog/R-003.md
  - A-001
recommended:
  option: b
  reason: It keeps the backend stateless and offloads durability of the only copy of the Owner's data, which matters more
    than the small saving of SQLite. This holds if ADR-001 option a is chosen.
