context:
  text: One Owner uses the app on a phone; there is no sign-up, sharing or other role. The connection is assumed always available
    at this stage and offline use of the catalog is out of scope. Label photos must be uploaded from the phone. No architecture
    or code exists yet. This decides the client technology and where the backend runs. Hosting cost limits are not stated
    (A-001).
  cites:
  - knowledge/product-core.md
  - REQ-007
  - REQ-003
  - A-001
options:
- key: a
  summary: Installable web app (PWA) served by one backend container on a managed container platform. The camera and photo
    upload use the browser file and camera input.
  satisfies:
  - REQ-003
  - REQ-007
  pros: One codebase, no app-store release, works on the phone, and the single-user scale needs only one small container.
  cons: Limited access to native device features; offline use is not offered, which is acceptable because it is out of scope.
  cost: Platform and domain fees are not stated by any source; open assumption A-001.
  reversibility: costly
  risks: Browser camera behaviour differs between phones; the client would have to be rewritten if native features are later
    needed.
  constraints:
  - id: ADR-001/C-001
    statement: The client talks to the backend only through versioned interfaces (IF-n) and never reaches the data store or
      a recognition provider directly.
    kind: dependency
    check: review
  - id: ADR-001/C-002
    statement: The backend runs as one stateless deployable unit; durable state lives only in the store chosen by ADR-003.
    kind: deployment
    check: review
  affects:
  - CMP-001
  - CMP-002
  consequences: Client and backend ship from one repository and one pipeline; hosting is a managed container platform.
  cites:
  - knowledge/product-core.md
  - REQ-007
  - A-001
- key: b
  summary: Native cross-platform mobile app plus a hosted backend.
  satisfies:
  - REQ-003
  pros: Better camera and device integration.
  cons: Needs app packaging and installation steps and two build chains, which is heavy for one user.
  cost: Developer account and release effort are not stated; open assumption A-001.
  reversibility: costly
  risks: Slower delivery of the first requirements; release friction for every fix.
  constraints:
  - id: ADR-001/C-003
    statement: The mobile client uses only the backend's versioned interfaces.
    kind: interface
    check: review
  affects:
  - CMP-001
  - CMP-002
  consequences: Adds a mobile build and distribution path to DevOps.
  cites:
  - knowledge/product-core.md
  - A-001
- key: c
  summary: Local-first app with all data on the phone and no backend.
  satisfies:
  - REQ-007
  pros: No hosting cost and no server to run.
  cons: Photo recognition needs a provider key that would sit on the device; no backup or second device; a lost phone loses
    the catalog.
  cost: No hosting cost; effort to build sync later is not stated (A-001).
  reversibility: one-way
  risks: Migrating to a backend later means moving data off the device; one-way because device-only data has no copy to recover.
  constraints:
  - id: ADR-001/C-004
    statement: No provider secret is stored in the client.
    kind: technology
    check: review
  affects:
  - CMP-001
  consequences: There is no backend component; CMP-002 would not exist.
  cites:
  - knowledge/product-core.md
  - A-002
recommended:
  option: a
  reason: One user on a phone with an always-available connection (REQ-007 scope) needs no store release, and a backend keeps
    recognition provider secrets off the device. It is the simplest option that meets REQ-003.
