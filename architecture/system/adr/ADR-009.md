context:
  text: ADR-001 a says client and backend ship from one repository and one pipeline. CMP-001, CMP-002 and CMP-003 have empty
    code_paths; the Developer needs a layout so code_paths and .staff/code.yml can be filled (S-DEV-004). ADR-005/C-003 allows
    only CMP-003 to call a recognition provider, and CMP-002 may depend only on CMP-003 (CMP-002 allowed_dependencies), CMP-001
    only on IF-001. Other areas will later add modules to CMP-002 (CMP-002 responsibilities). Directory names below are language-neutral;
    the follow-up run applies the ADR-007 choice. Architecture documents stay under architecture/ and requirements under requirements/.
  cites:
  - ADR-001
  - ADR-005/C-003
  - architecture/system/components/CMP-002.md

options:
- key: a
  summary: 'Two top-level directories: client/ for CMP-001 and backend/ for CMP-002, with CMP-003 as a clearly named label-reader
    folder inside backend/. Tests sit beside each part''s code.'
  satisfies:
  - REQ-003
  - REQ-007
  pros: Simple; matches the two build chains and one container.
  cons: The CMP-003 boundary is a folder convention; a dependency rule is harder to enforce than a package boundary.
  cost: No cost known; effort not stated (A-008).
  reversibility: two-way
  risks: Code outside label-reader/ may import the provider client unnoticed unless a rule checks it.
  constraints:
  - id: ADR-009/C-001
    statement: CMP-001 code is under client/, CMP-002 code under backend/ except backend/label-reader/, and CMP-003 code under
      backend/label-reader/. Code under client/ does not import from backend/.
    kind: dependency
    check: review
  - id: ADR-009/C-002
    statement: Only code under backend/label-reader/ imports the recognition provider client (ADR-005/C-003).
    kind: dependency
    check: review
  affects:
  - CMP-001
  - CMP-002
  - CMP-003
  consequences: 'code_paths: client/**, backend/**, backend/label-reader/** (CMP-002 excludes the last).'
  cites:
  - ADR-005/C-003
  - A-008
- key: b
  summary: 'Three top-level packages: client/ (CMP-001), backend/ (CMP-002) and label-reader/ (CMP-003) as a separate package
    with its own manifest and tests, imported by backend/ in the same container build.'
  satisfies:
  - REQ-003
  - REQ-007
  pros: The CMP-003 boundary and the CMP-002 to CMP-003 dependency are visible in package manifests, so a dependency tool
    can enforce ADR-005/C-003 and allowed_dependencies; CMP-003 tests run alone.
  cons: One more package to build and version inside the repo; slightly more setup.
  cost: No cost known; effort not stated (A-008).
  reversibility: two-way
  risks: Package setup overhead for a small module.
  constraints:
  - id: ADR-009/C-003
    statement: CMP-001 code is under client/, CMP-002 under backend/, CMP-003 under label-reader/. client/ declares no dependency
      on backend/ or label-reader/; label-reader/ declares no dependency on backend/ or client/.
    kind: dependency
    check: review
  - id: ADR-009/C-004
    statement: Only label-reader/ depends on the recognition provider client; backend/ reaches the provider only through label-reader/'s
      public entry point.
    kind: dependency
    check: review
  - id: ADR-009/C-005
    statement: A conformance rule under architecture/system/conformance/ is added by the Developer's setup to check these
      package dependencies with the stack's dependency tool.
    kind: other
    check: review
  affects:
  - CMP-001
  - CMP-002
  - CMP-003
  consequences: 'code_paths: client/**, backend/**, label-reader/**.'
  cites:
  - ADR-005/C-003
  - architecture/system/components/CMP-002.md
  - A-008
- key: c
  summary: One application directory app/ holding both the client (app/web/) and the server (app/server/ with the label-reader
    in a subfolder), built as one project.
  satisfies:
  - REQ-003
  - REQ-007
  pros: Fewest files and one manifest; trivial build.
  cons: Client and server dependencies mix in one manifest, so the secret-free client rule (ADR-001/C-001) cannot be seen
    from dependencies; the component boundaries are only folders.
  cost: No cost known; effort not stated (A-008).
  reversibility: costly
  risks: Server-only code or keys may be bundled into the client by mistake; splitting later moves every file.
  constraints:
  - id: ADR-009/C-006
    statement: Client code under app/web/ never imports from app/server/, and the client bundle is checked to contain no provider
      key or server-only module.
    kind: dependency
    check: review
  affects:
  - CMP-001
  - CMP-002
  - CMP-003
  consequences: 'code_paths: app/web/**, app/server/**, app/server/label-reader/**.'
  cites:
  - ADR-001/C-001
  - A-008
recommended:
  option: b
  reason: A separate package makes the CMP-003 boundary and allowed_dependencies machine-checkable (S-ARCH-026) for the cost
    of one extra manifest, and ADR-005/C-003 is the constraint most worth enforcing mechanically.
