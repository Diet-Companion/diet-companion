context:
  text: R-008 says changing a dish's products or amounts creates a new dish and the old one stays unchanged. It says nothing
    about the name. R-010 allows two dishes with the same name. For products, R-005 edits name, brand, shop and portion example
    in place, and REQ-006/AC-018 shows a product renamed in place keeps its id. The ticket asks the design to say whether
    a name-only dish change edits in place. The answer decides whether past records show the old or the new dish name.
  cites:
  - R-008
  - R-010
  - R-005
  - REQ-006/AC-009
  - REQ-006/AC-018
  - Diet-Companion/diet-companion#92
options:
- key: a
  summary: 'A name-only change updates dishes.name in place: same id, response 200 with versioned false. A change to lines,
    including their order, records a new dish (201, versioned true).'
  satisfies:
  - REQ-006
  - REQ-006/AC-009
  pros: Follows R-008 literally (products or amounts). A typo fix does not retire a dish or leave a chain of look-alike dishes.
    Matches how R-005 treats product names.
  cons: Past log entries and plans show the new name, so a name is not frozen history.
  cost: 'Small: one branch in editDish. Build effort not stated (A-008).'
  reversibility: two-way
  risks: The Owner may expect a renamed dish to leave old records showing the old name. Mitigated by the explicit answer to
    this question.
  constraints:
  - id: ADR-013/C-001
    statement: editDish applies a request that changes only the name by updating dishes.name of the same row, returns 200
      with versioned false and the same id, and does not touch dish_lines. A request that changes lines records a new dish
      in one transaction (ADR-012/C-004). A request that changes nothing records nothing and returns 200 with versioned false.
    kind: interface
    check: review
  affects:
  - CMP-002
  - IF-001
  consequences: A dish name can change under a past record. Names are not unique, so no uniqueness check is needed (R-010).
  cites:
  - R-005
  - R-008
  - R-010
  - A-008
- key: b
  summary: Every change, including the name alone, records a new dish and retires the old one.
  satisfies:
  - REQ-006
  - REQ-006/AC-009
  pros: Past records always show the name they were made with. One edit rule for the whole dish.
  cons: Reads R-008 wider than it is written. A typo fix replaces the dish and the Owner's next plan must pick the new id.
    Many versions for trivial edits.
  cost: Small. Build effort not stated (A-008).
  reversibility: two-way
  risks: Surprising for a rename, and it diverges from product behaviour in REQ-006/AC-018.
  constraints:
  - id: ADR-013/C-002
    statement: editDish records a new dish for any change of name or lines and sets replaced_by on the old dish (ADR-012/C-004).
      A request that changes nothing records nothing and returns 200 with versioned false.
    kind: interface
    check: review
  affects:
  - CMP-002
  - IF-001
  consequences: Renaming always changes the dish id the client must use.
  cites:
  - R-008
  - REQ-006/AC-018
  - A-008
recommended:
  option: a
  reason: R-008 names products and amounts only, and R-005 treats product names as in-place edits, so a rename is the smallest
    change that follows the written rules.
