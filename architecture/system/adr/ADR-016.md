context:
  text: 'A range change made on day D applies from D (AC-005), so the server must know what D is. There is one Owner. No source
    states when a day starts; the operator named the Owner zone as Europe/Rome (A-028). CMP-002 already has an injectable
    clock (CMP-002 testability seam_clock), and tests fix it through startApi({now}) (tests/api/support/api.ts). The reviewer
    asked on #129 that tests fix the date through that seam (S-TESTAB-008). Closing a day may happen before the day ends (R-013),
    so the boundary matters for planning today and the next day.'
  cites:
  - REQ-009/AC-005

options:
- key: a
  summary: One IANA time zone set in deployment configuration. A day runs from 00:00 to 24:00 local time. Today is the date
    of the injectable clock instant in that zone. The server refuses to start when the setting is missing or is not a valid
    zone.
  satisfies:
  - REQ-009/AC-005
  - REQ-009/AC-006
  pros: Fits one Owner. No new data and no new interface operation. Tests set the instant with the clock seam and the zone
    with configuration. Daylight saving is handled by the zone database.
  cons: Changing the zone means changing configuration and redeploying. Travel across zones is not supported.
  cost: One setting and one date function in CMP-002. Build effort not stated (A-008).
  reversibility: two-way
  risks: A wrong zone puts the day boundary at the wrong hour, so a late-evening save would land on the wrong day. Mitigated
    by a startup check and a test around midnight at the boundary.
  constraints:
  - id: ADR-016/C-001
    statement: Today is computed only in CMP-002 by one function from the injectable clock and the configured IANA zone. The
      day starts at 00:00 local time. No handler takes today's date from a request.
    kind: other
    check: review
  - id: ADR-016/C-002
    statement: The zone comes from one deployment setting. CMP-002 fails at start when it is missing or not a valid IANA zone
      name. Tests set it per run and fix the instant through startApi({now}).
    kind: deployment
    check: review
  - id: ADR-016/C-003
    statement: Clients and other areas get today's date from IF-001 (as_of in getTargetRanges) and never compute it from the
      device clock for a range or a day boundary.
    kind: interface
    check: review
  affects:
  - CMP-002
  - CMP-001
  - IF-001
  consequences: Every dated feature (journal, closing, planning) uses the same function and the same boundary.
  cites:
  - REQ-009/AC-005
  - CMP-002
  - S-TESTAB-008
  - A-008
- key: b
  summary: The Owner's time zone is stored as a setting in the database, chosen on first use and changeable later. Today is
    computed server-side from the clock and the stored zone.
  satisfies:
  - REQ-009/AC-005
  - REQ-009/AC-006
  pros: The Owner can change the zone without a redeploy and can follow a move.
  cons: A new table, new IF-001 operations and a new first-use step, none asked for by REQ-009. A zone change shifts what
    today means for dates already saved.
  cost: New migration, operations and screen. Build effort not stated (A-008).
  reversibility: costly
  risks: Changing the zone mid-day can make one calendar date appear twice or be skipped. Adds scope beyond REQ-009.
  constraints:
  - id: ADR-016/C-004
    statement: The zone is read from a settings row owned by CMP-002, with a default that is required before the first range
      can be saved. Today is computed only in CMP-002 as in ADR-016/C-001.
    kind: data
    check: review
  affects:
  - CMP-002
  - CMP-001
  - IF-001
  consequences: IF-001 needs a settings operation in a later version.
  cites:
  - REQ-009
  - A-008
- key: c
  summary: The client sends its own local date with each save and read, and the server trusts it.
  satisfies:
  - REQ-009/AC-005
  pros: No server-side zone. Follows the phone wherever the Owner is.
  cons: The server has no say in what today is. A wrong device clock or a replayed request can backdate a range and rewrite
    a past day's range. Tests would fix the date in the client, not at the clock seam.
  cost: Least server work. Build effort not stated (A-008).
  reversibility: costly
  risks: Breaks AC-006 when the device clock is wrong, and bypasses the clock seam that S-TESTAB-008 relies on.
  constraints:
  - id: ADR-016/C-005
    statement: Requests that save or read ranges carry a local date, and CMP-002 uses it as given, within one day of the server
      clock.
    kind: interface
    check: review
  affects:
  - CMP-002
  - CMP-001
  - IF-001
  consequences: IF-001 requests carry a date, which makes backdating possible by design.
  cites:
  - REQ-009/AC-006
  - S-TESTAB-008
  - A-008
recommended:
  option: a
  reason: One Owner needs one zone, so a configured zone is enough (REQ-009). It keeps the date under the server clock seam
    (S-TESTAB-008), adds no data or interface, and cannot be backdated by a client. Option b adds scope no requirement states;
    option c breaks AC-006 on a wrong device clock.
