options:
- key: a
  summary: 'TypeScript end to end. Client: React with Vite as an installable PWA (web manifest, service worker for installability
    only). Backend: Node.js LTS with Fastify; CMP-003 is a module in the same process. Tests: Vitest for unit tests; integration
    tests run Fastify in-process against a real PostgreSQL started for the test run, with CMP-003 pointed at a recorded mock;
    Playwright for the client''s phone-sized flow against a fake backend.'
  satisfies:
  - REQ-003
  - REQ-007
  - ADR-001/C-001
  - ADR-001/C-002
  pros: One language and one toolchain, types shared between client and backend; the backend can serve the built client bundle
    directly (CMP-001 deployment); Anthropic and PostgreSQL client libraries are mature; small container image.
  cons: Runtime type safety needs schema validation at the edges; Node single-threaded, which is acceptable for one user.
  cost: No licence or service cost is known for these tools; build effort is not stated by any source (A-008).
  reversibility: costly
  risks: Cold-start time of Node on Cloud Run is unmeasured (A-009). Dependency churn in the JavaScript ecosystem needs lockfiles
    and update care.
  constraints:
  - id: ADR-007/C-001
    statement: CMP-001 is a TypeScript React single-page PWA built to static files; CMP-002 and CMP-003 are TypeScript on
      Node.js LTS, with the dependency lockfile committed.
    kind: technology
    check: review
  - id: ADR-007/C-002
    statement: Unit tests use Vitest. Backend integration tests run against a real PostgreSQL instance (not an in-memory substitute)
      and replace the Anthropic API with a recorded mock at a process boundary (ADR-005/C-003).
    kind: technology
    check: review
  - id: ADR-007/C-003
    statement: The client's end-to-end flow tests use Playwright with a phone-sized viewport against a fake backend base URL
      (CMP-001 seam_external_dependencies).
    kind: technology
    check: review
  affects:
  - CMP-001
  - CMP-002
  - CMP-003
  consequences: One build and one container image from one pipeline (ADR-001 consequences). Client types can be generated
    from IF-001's spec.
  cites:
  - ADR-001
  - ADR-005/C-003
  - A-008
  - A-009
- key: b
  summary: 'TypeScript React PWA client (as in a) with a Python backend: FastAPI, CMP-003 as a module. Tests: pytest for unit
    and integration tests against a real PostgreSQL and a recorded mock of the provider; Vitest and Playwright for the client.'
  satisfies:
  - REQ-003
  - REQ-007
  pros: FastAPI generates an OpenAPI document from code, which eases the implemented-interface check; concise validation models.
  cons: Two languages and two toolchains; types are not shared with the client except by generation; the container serves
    the client bundle as static files from a second tool chain's output.
  cost: No licence cost known; build effort not stated (A-008).
  reversibility: costly
  risks: Python cold start and image size on Cloud Run are unmeasured (A-009). Two dependency ecosystems to maintain for one
    person.
  constraints:
  - id: ADR-007/C-004
    statement: CMP-001 is TypeScript React; CMP-002 and CMP-003 are Python with FastAPI, with pinned dependency lockfiles
      for both.
    kind: technology
    check: review
  - id: ADR-007/C-005
    statement: Backend unit and integration tests use pytest against a real PostgreSQL; the provider is replaced by a recorded
      mock at a process boundary. Client tests use Vitest and Playwright.
    kind: technology
    check: review
  affects:
  - CMP-001
  - CMP-002
  - CMP-003
  consequences: Two build chains in one repository and one container image build with two stages.
  cites:
  - ADR-001
  - A-008
  - A-009
- key: c
  summary: 'TypeScript React PWA client with a Go backend using the standard net/http server and a PostgreSQL driver; CMP-003
    is a package in the same binary. Tests: the standard go test with testify-style assertions, integration tests against
    a real PostgreSQL and a recorded provider mock; Vitest and Playwright for the client.'
  satisfies:
  - REQ-003
  - REQ-007
  pros: A single static binary and a very small image; Go cold starts are usually short, which helps the add flow (QAS-001).
  cons: Two languages; fewer ready-made OpenAPI server helpers; more hand-written validation code.
  cost: No licence cost known; build effort not stated (A-008).
  reversibility: costly
  risks: More code for the same behaviour than a or b; cold-start benefit is unmeasured (A-009).
  constraints:
  - id: ADR-007/C-006
    statement: CMP-001 is TypeScript React; CMP-002 and CMP-003 are Go with module dependencies pinned in go.sum.
    kind: technology
    check: review
  - id: ADR-007/C-007
    statement: Backend tests use go test with a real PostgreSQL for integration and a recorded provider mock at a process
      boundary. Client tests use Vitest and Playwright.
    kind: technology
    check: review
  affects:
  - CMP-001
  - CMP-002
  - CMP-003
  consequences: A multi-stage container build produces the Go binary and the client bundle.
  cites:
  - ADR-001
  - QAS-001
  - A-008
  - A-009
- key: d
  summary: 'TypeScript React PWA client with a Kotlin backend on Spring Boot; CMP-003 is a package. Tests: JUnit 5 for unit
    tests, integration tests against a real PostgreSQL (Testcontainers) and a recorded provider mock; Vitest and Playwright
    for the client.'
  satisfies:
  - REQ-003
  - REQ-007
  pros: Strong typing and a very mature framework ecosystem for validation, sessions and database access.
  cons: JVM images are large and start slowly, which works against the cold-start concern (ADR-006/C-008); heavy for a single-user
    app.
  cost: No licence cost known; JVM memory needs may raise the Cloud Run instance size, with a cost not stated by any source
    (A-008, A-009).
  reversibility: costly
  risks: Cold start may lengthen the add flow beyond what QAS-001's typical time suggests; larger memory use may leave the
    free tier.
  constraints:
  - id: ADR-007/C-008
    statement: CMP-001 is TypeScript React; CMP-002 and CMP-003 are Kotlin on a supported JVM LTS with Spring Boot, with dependency
      versions pinned in the build file.
    kind: technology
    check: review
  - id: ADR-007/C-009
    statement: Backend tests use JUnit 5 with a real PostgreSQL for integration and a recorded provider mock at a process
      boundary. Client tests use Vitest and Playwright.
    kind: technology
    check: review
  affects:
  - CMP-001
  - CMP-002
  - CMP-003
  consequences: Two build chains and a heavier container image.
  cites:
  - ADR-006/C-008
  - QAS-001
  - A-008
  - A-009

  option: a
  reason: One language and toolchain suits one Owner and a single container that also serves the client bundle (ADR-001 a),
    and it lets client types come from IF-001. It keeps every accepted constraint. Cold start is unmeasured (A-009) and is
    checked after first deployment (ADR-006/C-008).
