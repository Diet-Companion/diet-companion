context:
  text: 'A day total and a day plan total are rounded to a whole number and compared with the range: green from minimum to
    maximum inclusive, yellow below, red above, with a signed number (R-012). The rounded total decides the colour (REQ-010/AC-025).
    A halfway value is rounded as the implementation language''s standard rounding does (REQ-010/AC-012). One function must
    serve the logged day and the plan (REQ-010/AC-023, AC-024). Meal totals are whole numbers with no colour (REQ-010/AC-013,
    REQ-015/AC-010) and no other warning is shown (REQ-015/AC-011). ADR-019/C-003 puts the weight and total function in CMP-002
    and leaves rounding to REQ-010 (A-040). The client takes dates from the server (ADR-016/C-003). Nutrient values are double
    precision in the database (migration 001), so sums carry floating-point noise.'
  cites:
  - R-012

options:
- key: a
  summary: The server computes it. One CMP-002 function rounds a total and compares it with its range; the day reads of IF-001
    return the rounded total, the range, the colour status and the signed number. The client shows them and computes none.
  satisfies:
  - REQ-010/AC-012
  - REQ-010/AC-023
  - REQ-010/AC-024
  - REQ-010/AC-025
  - REQ-015/AC-011
  pros: One implementation for log, plan, open and closed days. API tests on the clock seam and real PostgreSQL decide every
    R-012 boundary without a browser. Rounding sits next to the total function of ADR-019/C-003.
  cons: Every colour and number change is a server change. The response carries more fields.
  cost: One function and one response shape in CMP-002. Build effort is not stated by any source (A-034).
  reversibility: two-way
  risks: A client that recomputes anyway could drift from the server. Mitigated by the constraint and by test ids that expose
    the server values.
  constraints:
  - id: ADR-021/C-001
    statement: CMP-002 has one function that rounds a total and compares it with a range, used for the log and the plan, for
      open and closed days and for the ranges of ADR-020. It sums the unrounded per-entry values, normalises the sum to 6
      decimal places, then rounds once with Math.round (halves go up; totals are never negative, so 99.5 gives 100 and 1799.6
      gives 1800). Per-entry values are never rounded before the sum.
    kind: interface
    check: review
  - id: ADR-021/C-002
    statement: 'The status and signed number come from the rounded total only: a total below the minimum is yellow with a
      minus sign and the amount to the minimum; above the maximum red with a plus sign and the amount over it; from the minimum
      to the maximum green with a minus sign and the distance to the maximum, and 0 with no sign exactly at the maximum.'
    kind: interface
    check: review
  - id: ADR-021/C-003
    statement: Meal totals are rounded by the same rule and carry no range, colour or number. No operation returns a per-meal
      or per-product difference between plan and log, or a warning.
    kind: interface
    check: review
  - id: ADR-021/C-004
    statement: The client does not compute a total, a rounding, a colour or a signed number; it shows the values of IF-001.
    kind: dependency
    check: review
  affects:
  - CMP-002
  - CMP-001
  - IF-001
  consequences: IF-001 1.6.0 day sheets carry the result. The client has display code only.
  cites:
  - ADR-019/C-003
  - ADR-016/C-003
  - A-034
- key: b
  summary: The server returns unrounded totals and the ranges; the client rounds and compares with one client function used
    by the plan and log screens.
  satisfies:
  - REQ-010/AC-012
  - REQ-010/AC-023
  - REQ-010/AC-025
  pros: The server only returns sums and ranges. A colour or number change is a client change.
  cons: Rounding and the R-012 table are tested only through unit tests of the client or a browser. A second place where totals
    are interpreted. Unrounded doubles cross the interface.
  cost: One client function and unit tests. Build effort is not stated by any source (A-034).
  reversibility: two-way
  risks: Floating-point noise near a halfway or a boundary value decides a colour differently in the client than a later server
    check would. API tests cannot assert the result.
  constraints:
  - id: ADR-021/C-005
    statement: Day reads return the unrounded totals and the ranges. One client function rounds and compares, used for log
      and plan, with the rule and the table of option a.
    kind: interface
    check: review
  - id: ADR-021/C-006
    statement: Unit tests of the client function cover every boundary of REQ-010/AC-017 to AC-028.
    kind: other
    check: review
  affects:
  - CMP-001
  - CMP-002
  - IF-001
  consequences: IF-001 totals are unrounded numbers. The client owns the result.
  cites:
  - ADR-019/C-003
  - A-034
recommended:
  option: a
  reason: ADR-019/C-003 already puts the total function in CMP-002, one server function serves log and plan (REQ-010/AC-023,
    AC-024) and API tests can decide every boundary of R-012. The client then shows values and cannot disagree.
