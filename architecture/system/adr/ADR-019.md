context:
  text: Plan and log changes are refused on a closed day (REQ-013/AC-007, REQ-014/AC-011, R-013). Closing is REQ-011 and is
    not built, so nothing can close a day yet, but these ACs are ready and must be testable now. ADR-015/C-004 says a closed
    day keeps the ranges it was closed with on its own record. REQ-010 and REQ-015 will compare day and meal calories, protein
    and fat with the ranges. Product nutrient edits make a new product id (ADR-011), and dish lines never change (ADR-012/C-002),
    so an entry's nutrients never change for its exact ids.
  cites:
  - REQ-013/AC-007
  - REQ-014/AC-011
  - R-013
  - ADR-015/C-004
  - ADR-011
  - ADR-012/C-002
options:
- key: a
  summary: 'A days table with one row per day that has entries: day (primary key), closed_at (null until REQ-011 closes the
    day), created_at. Entry rows reference it. A mutation locks the day row and refuses when closed_at is set. Totals are
    computed on read from the entries.'
  satisfies:
  - REQ-013/AC-007
  - REQ-014/AC-011
  - ADR-015/C-004
  pros: The closed state and the later copy of the ranges have a home that exists now. A row lock makes closing and an entry
    change safe against each other. REQ-011 adds a table or columns without touching the entry tables. The guard is testable
    with a seeded closed day.
  cons: A day row is created on first use. A column exists before the feature that sets it.
  cost: One extra table in migration 007 and a lazy insert. Build effort not stated (A-034).
  reversibility: costly
  risks: Setting closed_at anywhere but the closing feature would freeze a day. Mitigated by the constraint and by seeding
    it for test environments only.
  constraints:
  - id: ADR-019/C-001
    statement: 'Migration 007 also adds days: day date primary key, closed_at timestamptz null, created_at timestamptz not
      null; entries reference days(day). The row is inserted with insert-on-conflict-do-nothing in the same transaction as
      the first entry.'
    kind: data
    check: review
  - id: ADR-019/C-002
    statement: closed_at is written only by the closing feature of REQ-011, which in one transaction also stores the day's
      range copy on its own record (ADR-015/C-004); until then it is null except in seeded test data. A mutation selects the
      day row for update and refuses with day.closed when closed_at is set; reads of a closed day work.
    kind: data
    check: review
  - id: ADR-019/C-003
    statement: Totals are computed on read by one function in CMP-002 for a kind (plan or log), a day and optionally a meal,
      and are never stored. A product entry weighs grams, or pieces times the piece_weight of its exact product id; a dish
      entry weighs the sum of its dish lines the same way. Calories, protein and fat are the per-100 g values of the exact
      product id times weight divided by 100, summed. Rounding is the business of REQ-010 and REQ-015 (A-040). A plan and
      a log use the same function.
    kind: interface
    check: review
  - id: ADR-019/C-004
    statement: A closed day's entries are never updated or deleted, so totals read from them stay equal; REQ-011 decides whether
      it also stores totals.
    kind: data
    check: review
  affects:
  - CMP-002
  - IF-001
  consequences: IF-001 day responses carry closed and editable. REQ-011 sets closed_at and adds the range copy without reshaping
    the entry tables.
  cites:
  - ADR-015/C-004
  - R-013
  - A-034
- key: b
  summary: No days table. A closed_days table (day primary key, closed_at) is created now and holds a row only for a closed
    day, written by REQ-011. Entries have no foreign key to a day. Totals are computed on read as in option a.
  satisfies:
  - REQ-013/AC-007
  - REQ-014/AC-011
  - ADR-015/C-004
  pros: No lazy day row and no foreign key. Smaller entry migration. The guard is testable with a seeded closed_days row.
  cons: No row to lock when the day is open, so a closing that runs at the same moment as an entry change can miss it. The
    range copy has no day record to join until REQ-011 creates one.
  cost: One small table. Build effort not stated (A-034).
  reversibility: costly
  risks: The closing and entry race. One Owner makes it unlikely, but the rule R-013 says a closed day never changes.
  constraints:
  - id: ADR-019/C-005
    statement: Migration 007 also adds closed_days (day date primary key, closed_at timestamptz not null). A mutation refuses
      with day.closed when a row exists for the day. Only REQ-011 inserts rows, in the same transaction as the range copy;
      seeded in tests only until then. Entries carry day without a foreign key.
    kind: data
    check: review
  - id: ADR-019/C-006
    statement: Totals are computed on read as in ADR-019/C-003 and never stored.
    kind: interface
    check: review
  affects:
  - CMP-002
  - IF-001
  consequences: REQ-011 may need its own day record for the range copy.
  cites:
  - ADR-015/C-004
  - A-034
recommended:
  option: a
  reason: A day row is where the closed state and the later range copy of ADR-015/C-004 belong, and its lock keeps a closed
    day from changing (R-013). It adds one small table now so REQ-011 does not reshape the entry tables.
