context:
  text: Closing a day must fix its totals and result (REQ-011/AC-001, AC-008, AC-010), a closed day never changes (R-013,
    REQ-011/AC-003) and a later product edit must not change it (REQ-010/AC-014, R-004). ADR-015/C-004 says a closed day keeps
    the ranges it was closed with on its own record and is never recomputed from target_ranges. ADR-019/C-004 says a closed
    day's entries are never updated or deleted, so totals read from them stay equal, and leaves to REQ-011 whether it also
    stores totals; ADR-019/C-003 says totals are computed on read and never stored. A nutrient edit makes a new product id
    (ADR-011) and dish lines never change (ADR-012/C-002), so an entry's nutrients never change. The days row is created with
    the first entry, so a day with no entries has no row until it is closed (migration 007).

options:
- key: a
  summary: New table day_ranges holds the ranges in force on the date, one row per nutrient that had a range, written when
    the day is closed. Totals and the result of a closed day are computed on read from its entries with the stored ranges.
  satisfies:
  - REQ-011/AC-001
  - REQ-011/AC-003
  - REQ-010/AC-014
  - ADR-015/C-004
  pros: 'Smallest change: one new table, and the rule that totals are computed by one function (ADR-019/C-003) stays whole.
    Entries of a closed day cannot change, so the totals stay equal. Open and closed days share the same total code, so there
    is nothing to keep in step.'
  cons: A later change to the total or rounding function would change the result of closed days. Protection rests on entries
    never changing and on tests.
  cost: One migration with one table and the close transaction in CMP-002. Build effort is not stated by any source (A-034).
  reversibility: costly
  risks: Changing the total or rounding code later silently changes closed days. Mitigated by REQ-010 putting changes to rounding
    out of scope and by tests that fix a closed day's numbers (REQ-010/AC-014). Backfilling a totals snapshot later is possible
    because entries never change.
  constraints:
  - id: ADR-020/C-001
    statement: 'Migration 008 is forward-only and adds only the table day_ranges: day date not null references days(day),
      nutrient text not null check in (calories, protein, fat), minimum integer not null check minimum >= 0, maximum integer
      not null check maximum >= minimum, primary key (day, nutrient). It inserts no rows and does not alter days, day_entries
      or target_ranges.'
    kind: data
    check: review
  - id: ADR-020/C-002
    statement: 'Only closeDay sets closed_at or writes day_ranges, in one transaction: insert the days row if missing (insert
      on conflict do nothing), select it for update, refuse with day.closed when closed_at is set, insert one day_ranges row
      for each nutrient that has a range in force on that date through the shared function of ADR-015/C-003, then set closed_at
      from the injectable clock. day_ranges rows are never updated or deleted. A day with no entries is closed the same way
      (REQ-011/AC-010).'
    kind: data
    check: review
  - id: ADR-020/C-003
    statement: A day with closed_at set reads its ranges only from day_ranges, never from target_ranges; an open day reads
      them through the ADR-015/C-003 function for its date. The plan of a closed day is compared with the same stored ranges.
    kind: data
    check: review
  - id: ADR-020/C-004
    statement: The totals of a closed day are computed on read from its entries by the function of ADR-019/C-003 and are not
      stored. Entries of a closed day are never changed (ADR-019/C-004).
    kind: interface
    check: review
  affects:
  - CMP-002
  - IF-001
  consequences: IF-001 1.6.0 day sheets carry closed_at and a result whose ranges_source is closed_copy for a closed day.
    CMP-002 owns day_ranges. ADR-019/C-003 and C-004 stay as they are.
  cites:
  - ADR-015/C-004
  - ADR-019/C-003
  - ADR-019/C-004
  - A-034
- key: b
  summary: As option a, and closing also stores the rounded calories, protein and fat totals of the log and of the plan in
    a new table day_totals. A closed day reads its totals and result only from the stored rows.
  satisfies:
  - REQ-011/AC-001
  - REQ-011/AC-003
  - REQ-010/AC-014
  - ADR-015/C-004
  pros: A closed day's numbers are fixed by data, whatever later happens to the total or rounding code. Reading a closed day
    needs no entry join.
  cons: Two sources of the same number once a day is closed. Contradicts ADR-019/C-003, which says totals are never stored.
    Six more rows per close and a second table. The plan of a closed day is frozen too, so its rows must be stored as well.
  cost: Two tables in migration 008 and more close code. Build effort is not stated by any source (A-034).
  reversibility: costly
  risks: The stored and the computed totals could differ if the function is changed later, and the product would show different
    numbers for open and closed days.
  constraints:
  - id: ADR-020/C-005
    statement: 'Migration 008 is forward-only and adds only day_ranges as in ADR-020/C-001 and day_totals: day date not null
      references days(day), kind text not null check in (plan, log), nutrient text not null check in (calories, protein, fat),
      total integer not null check total >= 0, primary key (day, kind, nutrient). It inserts no rows.'
    kind: data
    check: review
  - id: ADR-020/C-006
    statement: closeDay writes day_ranges and the six day_totals rows in the transaction of ADR-020/C-002, with each total
      rounded by the one function of ADR-021. A closed day reads its ranges and totals only from these rows. Rows are never
      updated or deleted.
    kind: data
    check: review
  - id: ADR-020/C-007
    statement: 'ADR-019/C-003 is superseded for closed days: their totals are stored. Open days still compute totals on read.'
    kind: interface
    check: review
  affects:
  - CMP-002
  - IF-001
  - ADR-019
  consequences: A new ADR or a superseding revision of ADR-019 is needed to retire its constraint C-003 for closed days. CMP-002
    owns two more tables.
  cites:
  - ADR-019/C-003
  - ADR-015/C-004
  - A-034
recommended:
  option: a
  reason: Entries of a closed day never change and a product edit makes a new product, so recomputing gives the same totals
    (ADR-019/C-004, R-004). Option a keeps ADR-019/C-003 whole, adds one table and has one total function for every day.
